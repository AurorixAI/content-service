## 0. Правила работы (читать перед каждой сессией)

Эти правила важнее любой отдельной задачи.

1. **Одна сессия = один PR.** Не начинай задачи следующей сессии, даже если текущая
   закончилась быстро. Закончил — останавливайся и отчитывайся.
2. **Не рефактори то, о чём не просили.** Увидел плохой код рядом — запиши в
   «Обнаруженные проблемы», но не трогай.
3. **Не добавляй зависимости молча.** Новый пакет = спросить сначала.
4. **Перед и после изменений — прогони метрики** (`make eval`, см. §5 С1) и покажи
   цифры до/после. Метрика упала — откатывай, не «дочинивай».
5. **Не чисти кэш пайплайна** (`PIPELINE_CACHE_DIR`, `backups/`) без явной просьбы.
   Он экономит десятки долларов и часы прогонов.
6. **Никогда не ломай main.** В конце сессии состояние запускается end-to-end.
   Не успеваешь — режь функциональность, а не оставляй сломанным.
7. **Не трогай прод-данные вслепую.** Любой скрипт, пишущий в `tasks_master`,
   сначала прогоняется с `--dry-run` и показывает диф. Массовые правки — только
   после бэкапа (`scripts/backup_algo_content.sh`).
8. **Тесты — только там, где указано в задаче.** Не покрывай всё подряд.

### Протокол завершения сессии (обязателен)

```bash
# 1. Ветка под сессию (от свежего main)
git checkout main && git pull
git checkout -b session-N-<краткое-имя>

# 2. ...работа...

# 3. Тесты локально — должны быть зелёные (см. §2 «Тесты»)
python -m pytest tests/ -q --tb=short <--deselect ...>

# 4. Обновить CLAUDE.md (§0.5 состояние + §4 реестр багов) и EVAL.md
# 5. Коммит + PR
git push -u origin session-N-<краткое-имя>
gh pr create --title "Сессия N — <название>" --body "<отчёт по форме §6>"

# 6. Дождаться CI. Всё зелёное → мерджить
gh pr checks --watch
gh pr merge --squash --delete-branch
```

**⚠️ Мердж в `main` автоматически деплоит на staging-сервер** (`algolab.me`,
`.github/workflows/deploy.yml`: push в main → test → deploy). Поэтому:
- мерджим **только при полностью зелёном CI**, красный чек = не мерджим, чиним;
- если сессия трогала миграции/схему БД — предупредить человека **до** мерджа.

### Definition of Done для любой сессии

- [ ] Все задачи сессии сделаны, либо явно перенесены с причиной
- [ ] Багфиксы сессии сделаны (у каждой сессии есть свой блок «Багфиксы»)
- [ ] Тесты зелёные локально и в CI
- [ ] Цифры записаны в `EVAL.md` (начиная с С1, когда харнесс появится)
- [ ] `CLAUDE.md` обновлён: §0.5 (состояние) и §4 (реестр багов)
- [ ] PR создан, CI зелёный, смерджен в main squash-ом
- [ ] Ничего из «Не делай» этой сессии не сделано

### Коротко для не-инженера (2026-09-04)

**Система собрана и проверена. Дальше упирается не в код, а в деньги и в одного
человека с учебником.**

Что сделано. Конвейер оцифровки — из PDF учебника в банк задач — работает
целиком, от распознавания страницы до записи. Он прогнан на шести настоящих
книгах. Вокруг него стоят проверки, которые не пускают в банк брак: задачу
с формулой, которая не отрисуется у ученика, задачу без ответа, задачу, чей
ответ придумала модель, а не напечатала книга.

Что проверено. Отдельный прогон автоматического QA нашёл восемь дефектов —
все восемь починены, у каждого есть тест, который ловит именно его. Проверяли
не только тестами: каждый дефект воспроизводили запуском на реальных данных,
до и после починки. Один из восьми пришлось доделывать во второй заход —
починка была верной для новых данных, но не для тех, что уже лежали в базе;
нашли это, потому что пошли смотреть саму базу, а не поверили зелёным тестам.

Чего ждать не стоит прямо сейчас. В очереди стоит **421 готовая задача**,
и они **не** уедут в банк, даже если запустить перенос: у 414 из них вместо
настоящей темы стоит заглушка, у 7 темы нет вовсе — на все 421 приходится
**одна** тема на всех. Это не поломка, это защита: перенос сам себя
останавливает, когда видит, что все задачи свалены в одну тему, потому что
такое означает, что классификатор не отработал. Он не отработал по простой
причине — **закончились кредиты Gemini**. Разблокировать эти 421 задачу стоит
примерно 700 обращений к модели.

Второе, что нельзя купить или ускорить кодом: **эталонный набор** — несколько
десятков задач, вычитанных человеком по скану вручную. Без него нельзя
померить «стало лучше или хуже»: эталон, сгенерированный той же системой,
проверял бы систему саму собой. Это работа человека с книгой, и её никто,
кроме человека, не сделает.

Что нужно от вас: решение по кредитам Gemini и человек на вычитку эталона.
Всё остальное со стороны разработки готово и проверено.

| **Измерение качества** | **нет ничего** | **golden set, task_recall, latex_ned, compile_rate, numbering_gaps, KaTeX-компиляция, confidence/needs_review, HTML-вьюер** |

### Принятое решение (2026-08-23)

**Основа — `content-service`. Из `mathocr` забираем слой измерения качества и
несколько структурных модулей. Standalone-пайплайн `mathocr` — в архив.**

Почему основа именно content-service:
1. Он единственный **довёз результат** — 3 796 проверенных задач. mathocr за 7 сессий
   не отдал платформе ни одной.
2. Он решает задачу **целиком**. Оцифровка — это не «PDF → JSON», а «PDF → задачи,
   которые можно дать ученику». mathocr делает первые ~30% пути и останавливается
   перед самой ценной частью.
3. Главный блокер mathocr (429, недокачанные книги на 5–30%) — следствие free-tier
   ключей. Через Vertex AI этой проблемы нет.

Почему mathocr нельзя просто выбросить: в нём лежит **ровно то, чего у большой
системы нет** — контур измерения качества.

### Как прогнать книгу локально (разведано в С1)

**Пайплайн управляется оглавлением, а не файлом.** `_run_pdf_page_based` идёт по

Скрипт «под ключ» — `scripts/ingest_textbook.py`: извлекает TOC → заводит книгу
в БД → ставит job в очередь.

```bash

docker compose up -d --build
docker exec content-api alembic upgrade head

  --pdf /textbooks/книга.pdf --title "Алгебра, 7 класс" --class 7 \
  --language ru --country UZ
# выведет job_id; статус — GET /api/v1/jobs/{id}
```

Грабли (проверено, всё это отсутствует в свежем клоне):
- Нет ни `.env`, ни папки `textbooks/` — только `.env.example`. Создать руками.
- Доступ к Gemini обязателен: либо `GEMINI_API_KEY`, либо Vertex
  (`VERTEX_PROJECT_ID` + `GOOGLE_CREDENTIALS_PATH`).
- **`GOOGLE_CREDENTIALS_PATH` смонтирован в `docker-compose.yml` без дефолта** —
  пустое значение роняет `compose up` даже при работе через API-ключ.
- **`extract_toc` часто врёт на сканах.** Не случайно в `scripts/` лежит шесть
  `insert_toc_*.py` — для реальных книг оглавление заводили вручную. Если после
  ingest'а задач ноль, копать в `textbook_toc`, а не в extraction.

## 3. Что переносим из mathocr (проверено — этого здесь нет)

### 3.1 Eval-харнесс — главное

`mathocr/eval/{canonical.py, metrics.py, golden/}`.
- `canonical.py` — канонизация LaTeX перед сравнением (`\dfrac|\tfrac → \frac`,
  `\left(|\right) → (|)`, схлопывание пробелов). **Фундамент всех метрик, покрыт тестами.**
- `metrics.py` — `task_recall`, `formula_compile_rate`, `numbering_gaps`, `latex_ned`
  (нормализованный edit distance), `answer_join_coverage`. BLEU не использовать.
- `golden/` — формат ground truth (JSONL) + инструкция по вычитке страниц.

**Важно:** у content-service нет понятия «прогон книги в файл» — он пишет в БД.
Поэтому метрики считаем **против `tasks_master`**, а не против `tasks.json`.
Golden — вручную вычитанные страницы реальных учебников G7/G8.

### 3.2 KaTeX-компиляция формул ✅ перенесено в С2

`src/validate/katex.py` + `katex_compile.js` (npm `katex@0.16.11`, батч 400).

Здесь SymPy проверяет **ответы**, но никто не проверял, что **`question_latex`
рендерится**.

**Замерено в С2 — компиляции НЕДОСТАТОЧНО.** Класс артефактов делится надвое:

| Артефакт | KaTeX |
|---|---|
| `\left(\frac{14\pi}{3}ight)` — потерян `\` в `\right` | ✅ ловит (`\left` без пары) |
| `150^\\circ` — задвоенный в степени | ✅ ловит |
| `x \\cdot y` — задвоенный вне степени | ❌ **молча ок**: `\\` — валидный перенос строки |
| `rac{1}{2}` — потерян `\` в `\frac` | ❌ **молча ок**: рендерится как текст |

Последние два — тихая порча содержания: ученик видит бессмыслицу, а
`compile_rate` показывает 1.0. Поэтому нужен второй, лексический детектор —
`src/validate/latex_artifacts.py`. **Не трактовать `compile_rate = 1.0` как
«формулы верны».**

### 3.3 Чтение раздела «Ответы» из книги ✅ перенесено в С3

`mathocr/structure/answers.py` — детект хвостовых страниц-ответов, отдельный промпт
для плотного списка (`142. x=2; 3`), `norm_number` (снятие форматного мусора,
**не fuzzy**), join по точному номеру.

Сейчас content-service **генерирует ответы ИИ** (`AIAnswerSolver` в `enrichment.py`)
и потом героически их верифицирует — на это ушло 3 369 строк
(`answer_sympy_gate.py` 1 900 + `answer_verify.py` 1 469). **А в книге ответы уже
напечатаны.** mathocr забирает их напрямую: 109 ответов, **0 без пары**.
Это ground truth вместо догадки.

### 3.4 Структурный слой

- `structure/shared_context.py` — «В задачах 140–145 решите…» распространяется на
  диапазон. **Без него запись бессмысленна.** Плюс чистка ложных срабатываний
  (заголовок раздела, попавший в shared_context).
- `structure/merge.py` — склейка задачи, разорванной переносом страницы.
- `structure/ordering.py` — сортировка при двухколоночной вёрстке (скрембл 1,4,2,5,3,6).

### 3.5 Доверие и ручная проверка

- `validate/score.py` — `confidence.{ocr,structure}` + `needs_review` по порогам.
  **Переносить только с исправленным B1** (§4).
- `viewer/` — статический HTML: скан слева, карточки справа, KaTeX, сортировка по
  очереди ручной проверки. Один файл, никакого React.

### Что НЕ переносим

`mathocr/cli.py`, `extract/vlm.py`, `ingest/` — своя OCR-ветка на free-tier ключах.
Извлечение здесь лучше: Vertex AI, батчи по 4 страницы, sliding-window лимитер.
