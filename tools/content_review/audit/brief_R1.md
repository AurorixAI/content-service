# R1 — Детектор дефектов (Sonnet)

Вход: `audit/batch_NNN.json` — массив задач `{id, q, key, opts:[{i, v, why}]}` (школьная математика, 5–11 кл., выбор ответа; `i` — индекс дистрактора, 0-based).
Выход: `audit/find_NNN.jsonl` — по одной JSON-строке на ДЕФЕКТНУЮ задачу (чистые не писать). В чат вернуть ОДНУ строку: `batch NNN: checked N, defects M`.

Для КАЖДОЙ задачи реши её сам (python3/sympy через Bash — разрешено и желательно для вычислений), затем проверь:
1. `key` — ключ верен и полон (все корни, концы промежутков, верная форма).
2. `condition` — условие решаемо по тексту (нет ссылок на отсутствующие рисунок/таблицу/«эти примеры»/другое задание, текст не испорчен, нет пропущенных данных).
3. `multi` — в задаче несколько независимых вопросов (а), б) / 1), 2) / «…? …?» / пачка однотипных вычислений).
4. `correct_distractor` — какой-то неверный вариант на самом деле верен или равен ключу (0,5 и 1/2; n≤24 и n<25 для натуральных; равные множества).
5. `few` — меньше 2 различных неверных вариантов (для «да/нет» — меньше 1).
6. `expl` — объяснение варианта (`why`) не даёт его значение `v`, если выполнить описанную ошибку (пересчитай!), или противоречит само себе.
7. `latex` — сломанная разметка (непарный $, `\frac{a_{b}}{c}`, литеральный `\n`, мусор).

НЕ сообщать: стиль, общие-но-верные объяснения, эквивалентные записи верного значения, «можно было бы лучше».

Формат строки:
`{"id": "...", "cls": "key|condition|multi|correct_distractor|few|expl|latex", "opt": i|null, "what": "что не так (кратко)", "proof": "вычисление", "fix": "верное значение / как исправить"}`
Если у задачи несколько дефектов — несколько строк.
